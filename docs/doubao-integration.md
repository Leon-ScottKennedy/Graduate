# 豆包辅助分析

仅接入豆包（火山方舟），没有 Gemini、DeepSeek 或自动付费备用模型。项目不需要新增 SDK，后端用现有 httpx 调用 `https://ark.cn-beijing.volces.com/api/v3/chat/completions`。

## 配置

在火山方舟开通支持 JSON 输出的豆包文本模型，创建 API Key；把控制台提供的模型 ID 或推理接入点 ID 复制到模型配置。不要把豆包网页聊天账号、密码或 Cookie 当作 API Key。

只在本地 `server/.env` 添加以下两行，保留已有京东配置：

```dotenv
ARK_API_KEY=填写火山方舟APIKey
ARK_MODEL=填写已开通的模型ID或接入点ID
```

`.env.example` 是空白模板，不填写真实密钥。修改 `.env` 后重启后端。打开候选列表后自动评估，无独立 AI 页面、标签或分析按钮。配置参数会发送给火山方舟；密钥只由后端通过 Authorization 请求头传输，不进入浏览器、URL 或业务数据库。

## 免费试用

豆包 API 不是永久免费。使用平台提供的试用额度，并在火山方舟控制台开启“安心体验模式”，使免费额度接近耗尽时暂停服务。项目本身无法保证账号计费状态，不会自动开通付费、充值、切换其他模型或重试到备用服务。具体额度、模型资格和有效期以账号控制台为准。

官方说明：[免费推理试用额度](https://docs.volcengine.com/docs/ark/free-inference-quota?lang=zh)、[安心体验模式](https://docs.volcengine.com/docs/undefined/1465347?lang=zh)、[Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh)。

## 分工与边界

- 本地规则：明确接口、代际、板型和已知尺寸冲突阻止替换；推荐电源和预设档位仅提醒；缺失 BIOS、线材、尺寸信息待核验。
- AI：只提供补充建议和资料不足项，不修改配置、价格或规则结果。最多五条，必须引用本次上传的事实字段；引用不存在的字段、格式错误或试图返回额外裁决字段时拒绝整个 AI 结果。
- 引用输入字段只证明模型使用了哪些输入，不代表这些输入已被厂家核验，也不能保证模型自然语言完全正确。结果始终标记“AI 建议，需核验”。
- 上传的是当前配置的型号、规格和预设约束，不含 `.env` 或京东密钥。商品标题是数据，不是执行指令。AI 不联网检索新规格。
- 候选列表可见且有候选时，防抖 600ms 后先查询本地配置状态，再向 `POST /api/ai/candidates` 一次提交当前整机和整个候选批次。快速切换会取消尚未发出的调用。相同快照评估缓存 10 分钟，最多 30 个快照；不在店铺比价标签下调用模型。
- 结果仅对当前候选排序，并在卡片补充简短替换提醒，不修改配件或价格，不把 AI 意见升级为硬性兼容冲突。AI 不建议的候选排后，保留用户判断；本地明确冲突仍禁用替换。
- 配置改变或切换标签后清除旧结果，取消前端请求；后台已开始的调用仍可能消耗额度。未配置、额度不足或网络失败时保留规则候选，不额外弹出 AI 报错面板。
- 未配置、模型不可用、鉴权失败、额度不足、超时、格式错误均明确报错；规则检查继续可用，不伪造 AI 回答。每个后台进程最多一个正在处理的 AI 请求。

## 验证

后端 `tests/test_ai.py` 用模拟 HTTP 验证请求结构、密钥隔离、输入限制、引用检查、模型越权字段、异常和额度不足处理。它不证明豆包真实调用成功；密钥与模型未配置时不能真实联调。前端验证规则分类、建议不禁用替换、AI 提示及配置改变后结果失效。

### 2026-10-18 真实联调

用户配置密钥和模型后，使用 9000 元默认配置及两个 RTX 4070 SUPER 候选完成真实调用。初次模型把 evidence 字段名附加中文解释，被校验拒绝；已增加精确字段引用示例，继续保留严格校验，不接受模糊前缀匹配。按官方结构化输出建议设置 `thinking.type=disabled`，不输出深度思考内容。

修正后接口返回 200，两项候选均为 caution，提示核验电源余量、尺寸和供电接口，不直接判定不兼容。随后通过真实浏览器验证：候选列表自动请求 `/api/ai/candidates`，豆包结果进入卡片提示，未出现独立 AI 标签或运行错误。这证明本次配置的调用与页面链路已打通，不代表全部配件的分析质量已经验证，也不证明账号未启用付费。

结构化输出参数依据：[官方说明](https://docs.volcengine.com/docs/ark/structured-output-beta?lang=zh)。

### 悬浮装机助手

聊天现使用 Responses API，配置 `web_search` 工具、`sources=["doubao"]` 和最多两轮工具调用，关闭服务端会话存储。兼容性候选仍使用原结构化接口。聊天正文附带 API 返回的引用链接，只接受 HTTP(S) 地址，不把模型正文中的任意链接升级成已检索来源。检索结果不等于已观看视频，也不代表测试条件匹配。

后续开通联网内容插件后已真实验证成功，当前配置改为 `web_search`、`max_keyword=2`、`limit=6`（不再指定 Custom 版来源），最多两轮调用。浏览器请求返回 200、`searched=true`，来源区成功渲染 8 条引用链接，无前端运行错误。后端 49 项测试通过。测试只证明检索和展示链路可用，未逐条核验模型回复中的性能数字；回答质量仍依赖来源与测试条件匹配。

本次真实验证：豆包搜索 Custom 版返回 403 `AccessDenied`（web search activation）；联网内容插件返回 404 `ToolNotOpen`。模型能力页勾选不能证明组件已激活。需在同一 API Key 账号开通对应服务后再次验证。当前没有成功联网检索的证据。

悬浮助手通过 `/api/ai/chat` 调用同一个豆包模型，不再返回固定话术。每次发送当前配置、预算、用途、参考总价和本地检查结果，并附带最近 10 条对话供追问使用。密钥仅保留在后端；对话不写入数据库，配置变化后取消请求并清空旧对话。失败时显示原因并支持重试，助手只回答和建议，不直接替换配件。

真实浏览器连续两轮调用均返回 200，正确回答默认配置的显卡型号和 8943 元总价，并说明不是实时京东报价；预算变化后旧对话已清除。构建、类型检查、目标文件 ESLint 和 49 项后端测试通过。
