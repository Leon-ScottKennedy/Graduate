# 预算选配

`src/services/buildSelection.ts` 替代原“预算超过 11,000 就固定升级三件”的逻辑。

- 从八类参考候选中各选一件，总价按整数分求和，不超过输入预算。
- 游戏、创作、办公、AI 计算使用不同的预算分配权重；它们是启发式规则，不是机器学习结果或实测性能评分。
- 均衡搭配以输入预算为目标；控制预算以约 90% 为目标，候选限制下不保证恰好 90%；静音优先提高机箱和散热的预算占比，不代表已测噪声。
- 对 CPU/GPU 候选组合，按费用保留较优的其他配件组合，并综合用途分配与预算差额选择方案。不会通过修改候选价格或增加差额项目凑总价。
- 原型约束包括显卡最低预设电源功率、CPU 对主板/散热的预设档位、小机箱对 ATX 主板/360 水冷的限制。这不是完整兼容性检查，BIOS、尺寸、接口、真实功耗仍需核验。
- 无法组成预算内的完整配置时返回无方案；不得将预算上限改成实际总价，也不得把缺失配件隐藏。

候选来自 `src/data/mock/catalog.ts` 和 `budgetOptions.ts`。新增价格档位**全部为合成参考价格**，不来自京东抓取，不用于声明实时行情或现货可买。保留各类原始前两项，避免改变已有配置方案的索引含义。界面在总价处标注“预设参考价”，京东实际商品仍在独立区域展示，未确认标准型号前不混入配置报价。

实测参考结果：

- 游戏电竞/均衡搭配，预算 3,000 → 总价 2,982。
- 预算 9,000 → 总价 8,943。
- 预算 14,200 → 总价 14,142。
- 预算 28,600 → 总价 28,442。

这些只是当前参考目录的测试结果，不保证任意预算恰好花完。输入变化时自动重选；补充需求仍仅记录，手动替换也可能改变预算余量。

运行 `npm run test:build-selection`：覆盖 144 组预算、用途和偏好组合，检查配件齐全、总价一致、不超预算、原型约束，以及高预算回归。页面另行验证自动更新和各屏幕尺寸。
