# 免费邮箱验证码注册

项目使用现有 Python 标准库、SQLite 和个人邮箱 SMTP，不依赖付费短信、邮件 API 或新域名。使用你已有的 QQ / 163 邮箱即可；邮箱服务商可能有发信频率和风控限制，不保证无限发送。

## 配置真实邮件

1. 在邮箱网页设置中开启 SMTP 服务，生成客户端授权码。授权码不是邮箱登录密码，请勿发送到聊天或提交到 Git。
2. 在 `server/.env` 中填写以下配置（已有文件只补充这些项，不要覆盖其他密钥）：

```dotenv
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=你的完整QQ邮箱地址
SMTP_PASSWORD=你的SMTP授权码
SMTP_FROM=你的完整QQ邮箱地址
```

3. 重启 `npm run dev`，打开“登录 → 注册账号”，填写收件邮箱并发送验证码，填写收到的验证码和两次密码。
4. 注册后自动登录。智能装机页面可“保存配置”，在“配置方案 → 我的配置”查看、编辑或删除。退出后不能读取个人配置。

QQ 邮箱可从 https://mail.qq.com 进入设置；不同版本的入口名称可能是“账户”或“账号与安全”。网易邮箱需使用对应的 SMTP 主机和授权码，不要照搬 QQ 主机。

## 行为与限制

- 验证码 6 位、5 分钟有效、重发冷却 60 秒，旧码被新码替代，连续错误 5 次后失效，一次使用后删除。
- 邮箱每小时最多 5 次验证码申请，单 IP 每小时最多 10 次，全站每天最多 100 次；失败发送也会计入限额。
- 密码长度 8–128 位，以随机盐和 scrypt 哈希保存，不记录明文。验证码也不以明文保存，不返回浏览器、不写入日志。
- 会话使用 HttpOnly、SameSite=Strict Cookie，有效期 7 天，生产模式额外开启 Secure；退出会撤销服务端会话。
- 每个账号最多保存 20 套配置，所有读写在后端验证登录态和所属用户。数据保存在现有 SQLite 数据库中。
- 本机开发使用 Vite `/api` 代理。部署时建议让页面与 API 使用同一站点的反向代理，HTTPS 生产模式必须配置已有的安全选项。GitHub Pages 静态展示模式没有后端，无法提供真实注册登录。
- 账号登录不会赋予管理员权限，也不会解锁原来的付费 AI/商品采集访问码。

## 验证

在 `server` 目录运行 `.venv/Scripts/python.exe -m unittest discover -s tests -p test_accounts.py`。测试使用临时数据库和模拟邮件，不会实际发送邮件或消耗邮箱额度。真实投递需配置个人邮箱后完成一次人工收信测试。
