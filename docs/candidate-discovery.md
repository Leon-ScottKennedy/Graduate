# 全目录候选发现

这次修复的对象是数据获取流程，候选不再限于前端手写的型号数组。

## 查询与批量更新

切换配件后，页面调用 `POST /api/market/alternatives/discover`。首先读取 SQLite 的整类公开参考记录和已有京东、淘宝商品，再按当前规格跨品牌匹配。已登记候选立即显示，补查不阻塞本地比较。

缺少最新数据时，自动刷新当前类别的整张报价表，并通过已配置的京东、淘宝接口按规格关键词补采。关键词不绑定当前品牌或当前版本。整类报价缓存24小时，同规格采集冷却10分钟；即使预设候选都有价格，也不会据此跳过整个规格的查找。商品采集仍受原有平台限流及每日额度约束。

批量更新八类公开参考记录：

```powershell
server/.venv/Scripts/python.exe server/scripts/refresh_reference_catalog.py
```

加 `--force` 可主动重新读取全部八类来源。正常查询会共用缓存。数据写入 `public_reference_records`，保留类别、品牌、原始型号文字、整数分价格、来源链接、来源日期和查阅时间。一次更新失败或没有有效行时保留上次记录，不删除商品或报价历史。

2026-10-24实取八类来源共1374条：CPU145、显卡204、主板376、内存101、固态150、电源141、机箱81、散热176。这是原始参考记录数，**不是1374个已完成全部参数核验的可替换型号**。来源是[整类公开配件报价表](https://baojia.xinde8.com/)，为第三方未税渠道参考，不能视为官方店现价或库存证明。

## 规格与价格的边界

统一匹配覆盖八类：显卡完整芯片和显存，主板芯片组/平台/DDR/板型，内存DDR/总容量/条数/已知频率，固态容量/PCIe代际/M.2 NVMe，CPU平台/处理器级别/X3D属性，电源额定功率，机箱板型，散热类型。解析时先规范同一GPU的空格和连字符；XT、XTX、Ti、SUPER等后缀不能混用。Intel平台不再被错误地排除为非AM5。

同规格不等于实测性能相同。时序、主板供电、BIOS、显卡长度、扣具等没有证据时继续待核验。风冷塔数未注明时保留未知，只做同类风冷规格比较，不将其当作已核验的相同散热能力。无法可靠解析的来源记录保留在库中，不强行生成完整兼容参数。

来源内存如果明确只报单条价格，可以计算两条单买预算；名称、标签和来源说明都会写明“单条×2、不是原厂套装报价”，归为估算参考价。不能把单条价当双条套装价。没有代际或频率依据的型号不会补造这些属性。

商品只采用最新有效价格快照，过期或最新价格为空时不回退旧价。同品牌同规格商品优先自营后按价格选择，避免多个店铺复制出重复卡片；普通淘宝卖家、成色不明、多SKU混售、配件附件及类别不符继续剔除。标准目录已有准确型号时复用其ID，前端合并更新，不追加同一产品。

2026-10-25起，主列表默认“最多加价15%”：同规格筛选与兼容检查仍执行，便宜型号不限制降价幅度，直接展示并可替换。涨价超过上限的产品卡片完全隐藏，只保留隐藏数量和“查看全部价位”按钮；候选为空时也不自动展开，必须由用户主动解除价格限制。不能因低价放宽芯片、容量或平台条件，也不能改价凑数量。价格源不同时间、渠道与税费口径仍可能造成较大差异。

## 整体检查

后端运行后执行 `npm run audit:candidate-discovery`，自动遍历八类全部本地已登记型号，调用真实发现接口，结果保存为 `.tmp/candidate-discovery-audit.json`。2026-10-24在批量数据导入后检查164个型号，全部有候选；9个型号没有±15%内的备选，使用超限预览。这是当前目录快照，新增型号应重新运行审计。

后端测试包含未预先登记的模拟新芯片，保证发现机制不依赖现有50系名单；另检查跨品牌查询、重复店铺、容量与芯片歧义、空价/过期价、同规格冷却、采后入库、来源表批量解析及双条预算标签。运行：

```powershell
cd server
.venv/Scripts/python.exe -m unittest discover -s tests
```
