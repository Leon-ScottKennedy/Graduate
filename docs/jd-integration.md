# 京东精选池采集与查询

## 同型号店铺比价（2026-10-18）

### 页面职责调整

“店铺比价”仅保留当前型号报价，空状态提供“查看其他型号”入口，跳转“硬件对比”。同类商品列表已移到硬件对比，不在比价页重复展示。硬件对比优先展示已采集商品，预设型号折叠展示；支持最多选择三款，分别标注采集展示价与预设参考价，不混算最低价。采集商品缺少结构化规格时明确标注未核验，不能直接替换配置；预设型号继续沿用既有配置替换流程。以下早期的“同类参考”位置描述以本节为准。

右侧默认展示当前配置型号的店铺报价；其他商品收进“同类参考”。匹配要求品牌、型号及容量、DDR 代际、内存频率、版本等已知规格一致，信息不充分或冲突时不纳入报价。规则基于商品标题与品牌字段，采用保守匹配，仍可能漏掉标题格式不同的商品，不代表人工认证或全站覆盖。

同型号按来源店铺 ID 分组，缺少 ID 时使用规范化店铺名；店铺未知则不参与比价。同店重复采集或 itemId 变化仅合并展示，采用最新报价，保留原始记录和价格历史。最新价格失效时不回退旧低价；历史记录重新核对型号和店铺，避免商品改名后混入旧型号价格。

仅比较展示价，不含券后优惠和运费。单店不显示最低价或价差；多店显示相对当前采集最低价的差额。未匹配到商品时明确显示暂无报价，不自动加入其他型号，不修改配置预设价格。

`POST /api/jd/compare` 与 `POST /api/jd/compare/history` 仅查询本地数据，不调用京东。后者按报价组读取历史；刷新按钮才触发采集。散热分类排除硅脂、机箱风扇等附件；同类参考列表按相同标题、品牌与店铺去重展示，原始商品和快照不删除，因此展示条数可能少于历史采集计数。

## 当前实现（2026-10-18）

主流程已接入网页：`goods.jingfen.query`（频道 24）→ 按电脑组件类目清洗 → itemId/展示价保存 → `goods.bigfield.query` 场景 1 补充详情。
首次真实采集前 5 页共 250 条，保留 6 条硬件（显卡 2、电源 2、机箱 1、散热器 1），其余 244 条被排除；6 条详情全部成功。CPU、主板、内存、SSD 在该批样本中为零，不代表整个京东没有这些商品。

### 修复缺少类别（2026-10-18）

原先刷新始终请求前 3 页，CLI 也仅采样前 5 页，导致后续页的 CPU、内存、主板等一直没有机会进入本地库。现已增加 `jd_pool_progress` 持久化下一页、已扫页数、总页数和最近完成整轮扫描时间；`jd_pool_run_progress` 保存每次任务的页范围。
每页处理与游标推进在同一事务提交。后续页失败，下次从该失败页重试；不跳过失败页，也不重新扫描已完成的前缀。到达末页后下次从第 1 页开始新一轮。API 普通刷新采 3 页，空类别“补齐商品数据”最多采 30 页，提前遇到末页就结束；不在每次切换配件时自动请求京东。

已重新实际扫描当前全部 26 页、1,263 条记录，本次保留 36 条硬件，补充 20 条详情。合并已有记录后八类都有真实数据，其中内存 2 条；itemId 不同的记录不据标题强制合并。页面逐类验证均能读取，配置总价未改变。
覆盖统计代表本地已取得的记录，并非全站库存或全部型号。频道数量实时变化；空状态仍区分“尚有后续页面未采集”和“已扫描频道但该类未返回”，不以模拟数据替代。

### 页面和操作

- 启动后端及 Vite，打开智能装机，点击配置中的配件。右侧“京东商品”读取该类别本地数据，不请求京东、不替换配置。
- “筛选”只查本地已采集的品牌、标题，不是全站关键词搜索。
- “刷新数据”从持久化位置继续采集频道 24 的 3 页（每页最多 50 条），清洗入库后为最多 10 条硬件补充详情。是否完成整轮扫描由进度显示，不用单次任务完成状态代替整轮完成状态。
- 不存在的类别显示暂无数据。商品型号未核验，列出的是同类商品，不能当成配置中某型号的跨店最低价。
- 每条价格附带采集时间；“价格记录”展示同一 itemId 最近的快照。只有一个点时不展示趋势；重复采集追加快照。
- “采集记录”折叠展示任务状态、处理/排除计数与本地八类覆盖，避免占用主要操作区域。

### 清洗和数据边界

- 要求京东二级类目为“电脑组件”，三级类目精确匹配八类硬件；不从“处理器”“电源”等标题词推断，避免混入垃圾处理器、充电器和整机。
- 规范 HTML、全角字符和空白；缺失品牌/店铺记录待核验，不能用配置品牌补齐。
- itemId 是不透明的字符串，按实际返回值去重，不与 SKU 混用、不跨不同标识自动合并。内部产品 ID 为 `jd:item:{itemId}`。
- 商品链接保留返回的 materialUrl，补齐 HTTPS，限定已知京东商品域名；不拼接虚假的 `item.jd.com/{itemId}.html`。
- 只保存 `priceInfo.price` 展示价，数据库以整数分存储；不以券后价替代。空、零、负数、非有限值、异常精度，以及定金/服务类链接排除。
- 原始业务响应与每条商品保存到 raw_records；每项排除/转换依据存入 cleaning_events。详情按 itemId 关联，不从 mainSkuId/productId 推断为当前 SKU，不渲染上游 HTML。
- 已存在商品本次变为缺价/无效时追加 NULL 快照并移出有效列表，不回退旧价。没出现在有限采样中的商品仍保留原采集时间，不当作已下架。
- 详情请求失败保留有效报价并统计失败数量；后续页请求失败保留已成功的页，任务标记失败，页面明确报错。任务锁仅覆盖同一后端进程，当前不配置多 worker。

新增 `jd_pool_runs`、`jd_pool_items`、`jd_item_details` 表，不修改旧表，不清除旧记录。采集、清洗、数据库查询和 UI 分离，后续可接关键词接口并复用规则与价格快照。

### 独立采集命令

```powershell
server/.venv/Scripts/python.exe server/scripts/collect_jd_pool.py --pages 30 --restart
```

默认 3 页，允许 1 至 30 页；不加 `--restart` 时续采，CLI 最多补充 20 条详情。读取 `server/.env`，不需要安装官方 SDK或把 zip 纳入部署；SDK 压缩包仅用于对照调试脚本。

当前未实现：定时调度、跨进程限流/任务队列、自动型号匹配、兼容性推断、机器学习、淘宝。配置目录/总价继续用预设数据，右侧京东数据是真实的独立商品参考。

## 先前普通 SKU 路径与诊断记录

以下说明保留给后续权限开通时参考；不再是页面默认入口。

### 早期普通 SKU 入口

1. 在 `server/.env` 填写 `JD_APP_KEY`（后台 appkey）、`JD_APP_SECRET`（后台 secretkey）。
2. 按后端 README 启动后端，再启动 Vite。
3. 打开智能装机，点击配置中的配件，在右侧粘贴京东完整商品链接或纯数字 SKU，点击“获取商品”。每行一个，也支持逗号分隔，一次最多 10 个不同商品。
4. 成功结果按当前配件保存，下次打开恢复 SKU 列表和采集时间。新增商品时保留原 SKU 一起提交；每次展示最近一次成功查询的完整批次。

早期入口调用 `jd.union.open.goods.promotiongoodsinfo.query`（推广商品基本信息），参数 `skuIds` 为逗号分隔字符串，不带 sceneId。该接口在用户提供的基础权限列表中显示已开通。服务端向 `https://api.jd.com/routerjson` 发送表单 POST、MD5 签名；凭据和签名不经过浏览器，也不写入业务原始数据。

真实联调（2026-10-17）：用户提供的 SKU `100180790616` 在该基础接口上仍返回 `403：无访问权限`，尚未取得商品数据。需确认 `.env` 的 appkey 对应控制台中已开通权限的应用；不根据“有密钥”或“有接口列表”宣称调用成功。
大字段详情接口 `jd.union.open.goods.bigfield.query` 也已做探测：sceneId=2 返回 440，用户文档确认该场景另需申请；sceneId=1 的已尝试参数返回 441/网关 67，当前未找到可成功使用的参数组合，未作为界面默认接口。

官方入口：[京东联盟开放平台](https://union.jd.com/openplatform)。成功响应的适配、清洗与保存目前使用模拟数据测试，待权限解决后继续核对实际商品字段。联盟接口不保证覆盖京东全站商品或完整硬件参数。

### 早期 SKU 数据处理

- 原始响应与商品分别保存到 `raw_records`，清洗记录关联到原始商品。
- 缺少商品 ID、标题或展示价时排除；零、负数、非数值、非有限值及小于分的异常精度不进入有效报价。
- 清除标题 HTML、全角字符和多余空格；缺少品牌、店铺时记录待核验，不推断补齐。
- 排除标题含定金、补差、空盒、租赁及部分服务关键词的链接。这是规则筛选，不能保证识别全部异常商品。
- 同页相同 SKU 只保留首条有效结果。SKU 使用字符串；金额以整数分存储。
- 基础信息接口将 `unitPrice` 映射为展示价；保留的关键词搜索接口采用 `priceInfo.price`。不拿券后价填补缺失值，不混合价格口径。
- 每次搜索追加价格快照；已有商品本次缺价会保存 NULL，报价接口不回退为旧价格。
- 手动录入也不等于型号匹配，商品标记待核验，`hardware_id` 不自动关联，配置总价继续使用预设参考价格。同一个品牌的不同型号不会自动作为同一件商品比较。

`jd_searches` 保存查询摘要及清洗计数；`jd_search_results` 保留该次结果快照；新增 `jd_detail_queries` 保存配件集合标识、请求 SKU 和京东未返回的 SKU。旧表不修改、不清空历史数据。
只接受商品详情页完整链接和纯数字 SKU，不访问输入的 URL、不解析短链接；去掉链接跟踪参数后仅用 SKU 调用固定京东网关。
同批输入去重，京东未返回的商品单独列出，未请求的商品即使出现在响应中也不进入有效结果。读取缓存不调用京东，不把旧结果标成实时价格。
请求失败会记录失败任务；页面显示失败提示，不用演示报价替代。成功响应在清洗前单独提交，处理失败仍能排查原始数据。

### 官方 SDK 对照结果（2026-10-17）

使用用户下载的 `jd-api-sdk-python3-20261017.zip`，直接导入原版 SDK，未修改其签名和请求序列化；默认旧域名连接失败，改用 `https://api.jd.com`。

- `goods.promotiongoodsinfo.query` + 普通 SKU `100180790616`：仍返回 403。
- `goods.jingfen.query` + `eliteId=1`：返回 200，取得真实商品，使用 `itemId`，未返回普通 `skuId`。
- `goods.bigfield.query` + `goodsReq={sceneId:1,itemIds:[精选池返回的itemId]}`：返回 200，取得同一商品的图文详情。

因此已有可用的“精选池 → itemId → 场景 1 详情”链路，不能再将之前的 403 概括为整组密钥无效或所有商品接口不可用。测试精选池样品是日用品，尚未证明能覆盖所需电脑硬件，也不能将其当作用户提供的硬件 SKU。
对照时页面仍是普通 SKU 路径；2026-10-18 已改为上文精选池主流程。适配保留 itemId 原值及实际 materialUrl，不把 itemId 当成数字 SKU，不由详情中的 mainSkuId/productId 推断为请求商品 SKU。图文详情未返回价格，价格取同一 itemId 的精选池 priceInfo.price，缺价不补成零。

可重复运行（不入库，默认两次请求）：

```powershell
server/.venv/Scripts/python.exe server/scripts/check_jd_sdk.py
```

用 `--mode sku --sku 100180790616` 单独对照普通 SKU 接口。脚本只输出简要结果和京东 requestId，不输出密钥。
