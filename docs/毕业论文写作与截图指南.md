# NexBuild 毕业设计报告写作与截图指南

本指南依据用户提供的《王永康-毕业设计报告.doc》结构，以及当前 NexBuild 项目的实现编写。参考报告为人脸识别项目，其技术、业务、实验结论和个人信息不能直接沿用。本文件是写作计划，不是已完成的论文或测试报告。

## 1 题目与研究定位

建议题目：**基于 Vue 3 与 FastAPI 的人工智能辅助电脑装机系统设计与实现**。

也可以用较短题目：**基于人工智能辅助决策的电脑装机推荐系统设计与实现**。最终以导师审核及任务书题目为准。

系统采用 B/S 架构、前后端分离方案：Vue 3、TypeScript、Vite 实现前端，Python、FastAPI 提供业务接口，SQLite 保存账号、会话、配置和硬件相关记录；Three.js 与 GLB 资产实现首页三维硬件展示；通过外部大模型接口实现辅助分析。

论文的核心应是预算与用途约束下的装机决策，以及大模型输出与确定性规则的结合。三维展示是交互与可视化特色，不是人工智能算法。

必须准确区分：

- 本地选配是基于用途预算比例、评分和兼容约束的启发式组合搜索，没有训练机器学习模型，也不是实测性能预测。
- 在线 AI 通过后端调用外部模型，生成结构化方案或问答；不能写成自行训练大模型。
- 项目包含参考价和已记录报价，不应称为全网实时最低价。
- GitHub Pages 当前为静态演示；邮箱注册、数据库、在线 AI 等需要运行本地或独立部署的后端。论文演示与功能截图应在完整本地环境完成。
- 不把 mock 测试结果写成在线模型实际效果；不把未知参数写成已验证兼容。

## 2 参考报告的格式

已只读检查参考文件，共 25 页，结构为封面、目录、摘要、五章正文、参考文献、致谢、原创性声明。实际读取的主要版式如下，若学校有新版规范，应优先遵循学校规范。

- A4 纵向，四边页边距约 2.5 cm。
- 正文样本为宋体 12 pt（小四），首行缩进约两个汉字，1.5 倍行距。
- 一级标题样本为黑体 14 pt（四号）；二、三级标题样本为宋体 12 pt 加粗。
- 摘要标题样本为宋体 15 pt（小三）加粗。
- 图题样本为宋体 10.5 pt（五号），例如“图 4-3 系统登录代码实现”。
- 参考文件的部分标题使用自动编号与负缩进，不建议手工照抄缩进值；使用 Word 标题样式和多级编号。

建议复制模板另存为自己的报告，再替换内容；保留封面结构和学校规定声明，更新个人信息。目录通过标题样式自动生成，图题用“插入题注”，正文交叉引用图号。不要继承参考报告中重复图号、遗漏章节或不一致的表题。

## 3 章节安排及写作要点

建议正文约 20—26 页作为初步分配，不是学校强制要求；以任务书字数、导师要求及实际内容为准。第四章应占最大篇幅。

### 摘要

写约 300—500 字，分为问题、方法、功能、验证与结论四部分。先说明普通用户在预算分配、型号参数和兼容性方面遇到的困难；再介绍前后端架构、规则选配和大模型辅助分析；随后概括配置生成、硬件对比、邮箱注册、个人配置、3D 展示等实现；最后只填写实际完成的测试结果。

关键词建议：智能装机；大语言模型；Vue 3；FastAPI；三维可视化。

可改写的摘要开头：

> 针对个人电脑装机过程中硬件参数分散、预算分配困难以及配件兼容关系复杂等问题，本文设计并实现了 NexBuild 人工智能辅助电脑装机系统。系统采用前后端分离架构，通过 Vue 3 与 TypeScript 构建交互界面，利用 FastAPI 提供业务接口，并使用 SQLite 实现数据持久化。在配置生成方面，系统结合用途权重、参考价格与兼容性约束进行配件组合搜索；在辅助决策方面，通过外部大模型接口生成结构化建议，并对返回方案进行候选范围及兼容性校验。

后半段补实际功能和实测结论，不填未经测试的准确率、提升百分比或并发量。

### 第1章 前言（约2页）

1.1 研究背景与意义：硬件参数、平台接口、预算权衡和入门门槛；说明系统解决什么具体问题。

1.2 国内外研究与应用现状：围绕配置器、兼容性检查、对话式推荐和三维产品展示归纳已有方法，并结合真实文献讨论不足。本指南没有核验外部文献，正式写作前需检索和核实，不能编造作者、期刊、年份和 DOI。

1.3 本文主要工作：用一段介绍规则选配、AI 辅助、参数对比、账号配置管理、三维展示和测试，随后说明章节安排。

本章通常不放代码截图。

### 第2章 相关技术基础与理论支持（约2—3页）

2.1 Vue 3、TypeScript 与 Vite：响应式界面、组件化、类型约束和构建；结合本项目说明用途，不堆安装教程。

2.2 Python 与 FastAPI：接口、请求模型、参数校验、异常处理和异步外部调用。

2.3 SQLite：轻量文件数据库、事务、外键和参数化查询；解释适合毕业设计及单实例演示，同时说明多实例与高并发写入的局限。

2.4 大模型结构化输出与规则校验：事实输入、候选集、JSON Schema、Pydantic 校验、失败反馈与回退；说明大模型不直接替代兼容规则。

2.5 Three.js 与 glTF/GLB：场景、相机、独立硬件节点、材质、动画时间轴。

本章以原理与选型为主，不放大段源码。

### 第3章 系统需求分析与模块设计（约3—4页）

3.1 功能需求：预算/用途/平台输入、八类配件生成、候选替换、参数对比、AI 需求优化与问答、邮箱注册登录、个人配置保存、推荐方案导入和三维展示。

3.2 非功能需求：可维护性、响应性、账号隔离、凭证保护、弱网回退、主题和响应式适配。目标与实测结果分开写。

3.3 总体架构与模块划分：浏览器前端 → FastAPI → SQLite；FastAPI 再分别连接 SMTP 邮件服务与外部 AI 服务。区分本地静态硬件资料与后端数据来源，不把整个静态目录误画成数据库。

3.4 数据库设计：主图建议选 account_users、account_codes、account_sessions、account_configs，说明用户与配置的一对多关系及会话外键。硬件数据另画 hardware、products、price_snapshots；其余采集/审计表简述即可。

3.5 核心业务流程：输入预算用途 → 本地选配 → 兼容检查 → 展示配置；AI 流程另画“配置事实及候选 → 后端模型调用 → 结构校验 → 业务校验 → 有效方案应用/失败本地回退”。

### 第4章 系统设计与实现（约9—12页）

4.1 开发环境与项目结构：记录实际 Windows、Node.js、Python、数据库、浏览器版本，版本以本机命令为准；说明 src/views、components、services 和 server/app 的分工。不要用依赖安装长截图占页数。

4.2 邮箱注册、登录与会话：先放注册/登录界面，再介绍验证码发送、有效期、哈希、注册、Cookie 会话以及登录状态恢复；最后说明无效验证码和过期会话的处理。

4.3 预算选配与兼容性检查：放智能装机全景，再说明用途预算比例、按分计价、组合搜索、接口与尺寸等检查。说明这是启发式评分而非硬件真实性能评分。

4.4 候选配件与参数对比：放候选卡及双列对比弹窗，说明参数字段并集、差异标记、未知参数标记和替换后的整机校验。

4.5 AI辅助需求优化与装机问答：作为重点，放需求比例与成功分析结果，解释候选集和事实构造、外部API调用、结构化输出、候选ID约束、兼容校验、反馈修正、自动应用，以及AI失败时的本地回退。超预算方案可提示后应用，不能写成全部严格不超预算。问答与整机优化是不同输出路径，应分清。

4.6 推荐方案与个人配置：介绍推荐方案进入智能装机、登录后保存/查询/删除个人配置和未登录拦截；放界面与按用户ID查询代码，不放真实用户记录。

4.7 首页三维模型与主题适配：用装配、半拆解、完全拆解三张同视角图说明效果；介绍独立节点、25秒循环、统一进度插值、水冷管形变及主题材质过渡。现有代码未接入 OrbitControls，不能把历史讨论过的360°拖动旋转写成当前已实现功能。

每小节按“功能目的 → 页面效果 → 关键代码 → 执行过程和异常处理”展开。每张代码截图后至少有一段说明，不要只堆图。

### 第5章 系统测试与优化（约3—4页）

5.1 环境与方法：记录机器CPU/GPU/内存、分辨率、DPR、浏览器、网络、本地前后端启动方式、测试日期；说明自动化单元/接口测试与手工页面测试。

5.2 功能测试：覆盖有效/无效邮箱验证码、重复注册、错误密码、登录态、跨用户配置隔离、不同预算和平台、兼容冲突、参数缺失、推荐导入、AI有效输出/非法JSON/库外型号/超时/超预算、主题切换及循环动画。

5.3 性能与体验优化：Web Worker避免选配阻塞、按视口暂停渲染、限制刷新频率、资源并行下载与模型缓存、路由懒加载；如做性能对比，必须保持同一设备、主题、分辨率、DPR和清晰度，分别报告冷启动/缓存命中。传输gzip是无损传输压缩，DPR降低属于渲染清晰度降低，二者不能混称。

5.4 总结与不足：总结完成内容；说明价格更新、参数覆盖、在线服务依赖、SQLite部署规模及静态部署限制。若学校要求单独结论章，可在导师认可后增加第6章“总结与展望”。

参考文献、致谢、原创性声明按学校模板。模型素材与解码器的来源、许可应依据 public/models/nexbuild/SOURCES.md 等实际记录注明；不能把外部模型全部宣称为独立原创。

## 6 截图制作要求

- 代码图统一使用浅色编辑器背景，适合打印；字体适当放大，保留行号与函数，不拍整个桌面。
- 一张图只表达一个步骤；避免长代码、过多空白、终端混入和鼠标遮挡。无需为截图改写现有代码。
- 页面图统一浏览器尺寸，裁掉无关标签页、任务栏、开发工具与真实账号信息。
- Word里锁定图片纵横比，按正文宽度插入，优先“嵌入型”；图题放图下，并在前后文字引用。
- server/.env、SMTP授权码、AI密钥、Cookie、token、真实用户邮箱、密码哈希、真实验证码都不进入截图。
- 图前说明目的，图后解释输入、调用、判断、输出、异常处理；15—35行截图通常配100—180字说明即可。

代码说明示例：

> 如图4-12所示，后端接收模型返回内容后，首先通过Pydantic数据模型检查JSON结构及字段约束。对于整机优化请求，程序进一步判断用途比例是否被擅自修改，并验证方案中的配件标识是否属于提交的候选集合。若返回结果包含库外型号或无效结构，接口返回错误，前端不会直接采用该结果。通过该过程，系统将自然语言模型的建议限制在明确的数据和业务边界内。
